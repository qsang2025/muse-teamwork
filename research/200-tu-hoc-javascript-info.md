## 2. Học sâu: Promises, async/await + Fetch — mảng team dùng mỗi ngày

- **Async/await (đọc toàn văn 21/11/2026):** `async` trước hàm nghĩa là hàm luôn trả promise; `await` tạm dừng thực thi hàm tới khi promise settle mà không tốn CPU (engine làm việc khác trong lúc chờ). Điểm then chốt cho code extension: lỗi reject của promise được `await` biến thành exception — bắt bằng `try..catch` thường; quên `.catch` ở tầng ngoài cùng thì thành unhandled rejection. Bài học cũng nối thẳng sang `Promise.all` khi chờ nhiều request song song.
- **Fetch (đọc toàn văn 21/11/2026):** lấy response là quy trình **hai giai đoạn** — promise của `fetch` resolve khi có headers (kiểm tra được `status`/`ok`, chưa có body), sau đó phải gọi thêm một method đọc body (`text()`, `json()`, `blob()`, `arrayBuffer()`...). Bẫy quan trọng nhất: **HTTP 404/500 không làm promise reject** — chỉ lỗi mạng mới reject; body chỉ đọc được **một lần** (đọc `text()` xong thì `json()` thất bại). Đây chính là hai lỗi kinh điển khi viết extension lấy dữ liệu site: tưởng 404 là lỗi mạng, và đọc body hai lần.
- **Áp dụng cho vBook:** extension nào cũng fetch trang → parse → trích chương. Chuẩn rút ra: luôn kiểm tra `response.ok` trước khi đọc body, chọn đúng một method đọc body, bọc `await` trong `try..catch` và xử lý reject ở tầng ngoài cùng — ghi thành checklist khi build extension mới, thay vì mỗi extension tự xử lý một kiểu.

## 3. Học sâu: Modules + Classes — tổ chức code

- **Modules, introduction (đọc toàn văn 21/11/2026):** một file = một module; `export`/`import` thay cho biến toàn cục. Ba tính chất quyết định cách tổ chức code: module luôn ở strict mode, mỗi module có scope riêng ở tầng trên cùng, và module chỉ được thực thi **một lần** dù import nhiều nơi (exports dùng chung — đây là cơ chế để *cấu hình* module: export một object config, script đầu tiên ghi vào, các import sau dùng chung). Module chỉ chạy qua HTTP(s), không chạy qua `file://`.
- **Class basic syntax (đọc toàn văn 21/11/2026):** class trong JS thực chất là một loại function — constructor trở thành hàm, methods nằm trên `prototype`. Khác biệt thật so với viết tay kiểu cũ: class constructor bắt buộc gọi bằng `new`, methods không enumerable, code trong class luôn strict mode. Class fields (`prop = value`, kể cả arrow function làm field) giải quyết bài toán "mất `this`" khi truyền method làm event handler — điểm rất thực tế cho code giao diện.
- **Áp dụng cho team:** hub Node.js hiện là một file server; khi hub lớn lên, tách module theo đúng mẫu config-object ở trên là đường tự nhiên. Với extension vBook (mỗi extension là file JS độc lập theo mẫu app), giá trị không nằm ở việc đổi sang module (mẫu app không cho phép tùy tiện) mà ở *tư duy*: mỗi file tự chứa, không rò biến toàn cục, hàm dùng chung thì tách rõ ràng.

## 4. Học sâu: Browser events (Phần 2) — DOM và tương tác

- **Introduction to browser events (đọc toàn văn 21/11/2026):** ba cách gán handler (HTML attribute `on<event>`, DOM property, `addEventListener`) và vì sao cách thứ ba thắng: hai cách đầu chỉ giữ **một** handler cho mỗi event (gán mới ghi đè cũ), còn `addEventListener` giữ được nhiều handler, có options `once`/`capture`/`passive`, và là cách duy nhất cho một số event như `DOMContentLoaded`. Gỡ handler phải truyền đúng *cùng một* function object đã gán — truyền arrow function mới viết lại giống hệt vẫn không gỡ được.
- **Cấu trúc Phần 2 (theo TOC Lớp 2):** Document đi từ DOM tree → walking/searching (`getElement*`, `querySelector*`) → modifying document → styles/classes → sizes/scrolling/coordinates; sau đó mới tới Events (bubbling/capturing, delegation), UI Events, Forms, rồi Document/resource loading (`DOMContentLoaded`, async/defer) và Event loop (microtasks/macrotasks).
- **Áp dụng cho vBook:** extension đọc nội dung trang bằng selector — chương Searching + Walking the DOM là tài liệu tra cứu trực tiếp khi selector không khớp (live collection vs static, thứ tự duyệt cây). Event delegation là mẫu xử lý danh sách chương dài mà không gắn handler từng dòng. Với dashboard/3D office của team, `addEventListener` + delegation + `DOMContentLoaded` là bộ ba nền tảng nên chuẩn hóa.
